# 🏆 TenderHack SPB — Стратегия победы

> **Задача:** Интеллектуальный сервис поиска цен для [Портала поставщиков zakupki.mos.ru](https://zakupki.mos.ru/)
> **Формат:** 2 дня · 6 участников · Linux · без авторизации · без сохранения результатов

---

## 🔥 Боль бизнеса — простым языком

**Кто страдает:** Закупщики московских госучреждений — школы, больницы, департаменты. Все, кто покупает товары за бюджетные деньги через Портал поставщиков.

**В чём боль:**
Перед каждой закупкой по закону нужно обосновать **начальную максимальную цену контракта (НМЦК)** — доказать, что цена рыночная, не завышена. Для этого закупщик вручную:

1. Открывает Яндекс Маркет → копирует цены в Excel
2. Открывает Ozon → копирует цены в Excel
3. Открывает Wildberries → копирует цены в Excel
4. Гуглит прочие источники → копирует цены в Excel
5. Формирует таблицу вручную для приложения к тендеру

**Итог:** 2–4 часа на **один** товар. Тысячи закупщиков. Огромные потери рабочего времени бюджетных сотрудников.

**Дополнительные боли:**
- Опечатки в названиях → нерелевантные результаты
- Нет синонимов → "бумага А4" и "офисная бумага А4" ищутся отдельно
- Цены меняются → невозможно воспроизвести результат на следующий день
- Нет единого форматированного отчёта для аудиторов

## 💡 Концепция решения — **Наш продукт)**

> Не просто агрегатор цен — ИИ-помощник закупщика, который за 30 секунд делает то, на что раньше уходило 4 часа.

```
Закупщик вводит: "принтер лазерный А4 офисный"
                          ↓
          Собственная ИИ-модель (self-hosted)
          исправляет опечатки + расширяет запрос синонимами
          "лазерный принтер А4" / "принтер для офиса А4" / "ч/б принтер А4"
                          ↓
     Параллельный поиск по 4 источникам одновременно
     ┌─────────────┬──────────────┬──────────────┬──────────────────┐
     │Яндекс Маркет│     Ozon     │  Wildberries │  Рунет (динамич.)│
     └─────────────┴──────────────┴──────────────┴──────────────────┘
                          ↓
         Группировка результатов по источникам
         Фото · Название · Характеристики · Цена · Ссылка
                          ↓
         ИИ-анализ: медиана, диапазон, выбросы
                          ↓
     [Скачать PDF] → Справка об исследовании рынка для НМЦК
     "Среднерыночная цена: 8 400 ₽. Источников: 4. Дата: ..."
```

## ✨ WOW-факторы, которые выделят команду

### 1. 📄 Готовый документ НМЦК
Большинство команд сделают просто "таблицу цен". Мы делаем **готовый документ** — справку об исследовании рынка, которую закупщик сразу прикладывает к тендеру. Кнопка → PDF. Это закрывает реальную боль, а не просто автоматизирует поиск.

### 2. 🤖 Только собственный ИИ (без внешних зависимостей)
Заказчик не хочет зависеть от сторонних сервисов. Все NLP-задачи решаются **self-hosted** моделью:
- **Ollama** с моделью **Qwen2.5** (7B или 14B) — развёртывается за 5 минут, модель полностью под контролем заказчика
- Qwen2.5 показывает лучшие результаты на русскоязычных задачах NLP, чем Llama и Mistral!!!!!!
- Расширение синонимов, исправление опечаток, ранжирование результатов — всё внутри инфраструктуры заказчика
- Никакой зависимости от OpenAI, Anthropic, Yandex GPT и прочих внешних API
- Модель скачивается один раз, работает офлайн, данные закупок не покидают контур

### 3. 🌐 Динамический 4й источник (не фиксированный)
ТЗ прямо требует, что 4й источник **не может быть фиксированным**. Все внешние Search API запрещены — используем **прямой scraping поисковика через Playwright** (без API, бесплатно). DuckDuckGo или прямой поиск Яндекса/Google через браузер → парсинг органических результатов. Источник каждый раз разный — это именно то, что требует ТЗ.

### 4. 🔍 AI-расширение запроса
Пользователь вводит "бумага А4" → наша self-hosted модель генерирует: "офисная бумага А4", "бумага для принтера А4 80г/м²", "бумага копировальная А4". Результаты в 3 раза релевантнее.

### 5. 📊 Smart-ранжирование
Автоматически исключаем аномальные цены (слишком дёшево = подозрительно). Показываем: медиана, диапазон, рекомендованная цена для НМЦК.

### 6. 🗺️ Учёт региона
Отдельное поле "Регион" в поисковой строке. Влияет на результаты выдачи (маркетплейсы по-разному отображают цены с доставкой в регион). Это **явный критерий оценки** — 10 баллов.

### 7. 📐 BPMN-схема
**Обязательный deliverable** — без неё не оценят Этап 1 (5 мин питч). Схема процесса поиска цен в нотации BPMN с указанием каждого инструмента. Делает Амир в Bizagi/draw.io.

## 🔍 Подготовка к Code Review

> Code review на хакатонах — это не поиск багов. Жюри смотрит на **архитектурное мышление**, **читаемость** и **обоснованность решений**. Готовьтесь заранее.

### Что проверяют на code review

| Критерий | Что смотрят | Как подготовиться |
|----------|-------------|-------------------|
| **Архитектура** | Разделение ответственности, нет ли "всё в одном файле" | Разбить на слои: parsers / services / api / frontend |
| **Читаемость** | Понятные имена переменных, нет магических чисел | Нейминг на английском, константы вынести |
| **Обработка ошибок** | Что происходит при падении парсера | try/except с понятными сообщениями, fallback |
| **Документация** | README, комментарии к нетривиальным местам | README с архитектурой + инструкция запуска |
| **Тесты** | Хотя бы базовые unit-тесты | 2–3 теста на NLP-модуль и группировку |
| **Безопасность** | Нет ли открытых ключей, SQL-инъекций | .env файл, секреты не в коде |
| **Масштабируемость** | Можно ли добавить новый источник легко | Парсеры через единый интерфейс / абстракцию |

### Чеклист перед code review (выполнить в Час 05:00–06:00)


### Что говорить на code review

- **"Почему Ollama + Qwen2.5, а не внешний API?"** → Заказчик требует зависимости только под своим контролем. Qwen2.5 разворачивается локально через Ollama — модель скачивается один раз, данные закупок не покидают контур, нет риска отключения внешнего сервиса. Qwen2.5 показывает лучшее качество на русском языке среди open-source моделей.
- **"Почему именно эта архитектура?"** → Парсеры изолированы через единый интерфейс — добавление нового источника не трогает остальной код.
- **"Как масштабировать?"** → Горизонтально: добавляем воркеры в очередь задач. Вертикально: заменяем локальную модель на более мощную без изменения кода.
- **"Что если маркетплейс заблокирует?"** → Кэш в Redis (TTL 1 час), ротация User-Agent, экспоненциальный backoff, graceful degradation — показываем результаты из доступных источников.

## ⚙️ Технический стек

| Слой | Технология | Почему |
|------|-----------|--------|
| Backend | Python + FastAPI | Быстро, async, отлично для I/O парсинга |
| Парсинг | Playwright + httpx | JS-рендеринг + лёгкие HTTP-запросы |
| Self-hosted AI | **Ollama + Qwen2.5 (7B)** | Легковесная, быстрый инференс — жюри штрафует за тяжёлые модели |
| Опечатки | **symspellpy** (локально) | Внешние API запрещены, symspellpy работает офлайн |
| Frontend | React + TailwindCSS | Скорость разработки |
| БД | PostgreSQL + Redis | Кэш запросов (TTL 1 час) |
| PDF | WeasyPrint | Генерация справки НМЦК |
| Деплой | Docker Compose (Linux) | Требование: Linux |
| BPMN | draw.io / Bizagi | Обязательный deliverable |

### Anti-blocking стратегия

| Источник | Метод доступа |
|----------|--------------|
| **Wildberries** | Публичное API — без блокировок |
| **Ozon** | Playwright с задержками (API ограничен) |
| **Яндекс Маркет** | Playwright + ротация User-Agent |
| **4й источник (Рунет)** | Playwright → scraping DuckDuckGo напрямую (поисковые API запрещены!) |

```python
# Пример стратегии: экспоненциальный backoff
async def fetch_with_retry(url, max_retries=3):
    for attempt in range(max_retries):
        try:
            await asyncio.sleep(random.uniform(1.5, 4.0))  # рандомная задержка
            return await client.get(url, headers=random_ua())
        except RateLimitError:
            await asyncio.sleep(2 ** attempt)  # экспоненциальный backoff
```

## 🎯 Советы для победы над другими командами

### Технические преимущества
1. **Self-hosted AI на Qwen2.5** — модель полностью под контролем заказчика, данные не покидают контур. Это прямое попадание в требования: "только надёжные зависимости под нашим контролем". Qwen2.5 превосходит Llama на русскоязычных задачах — это подтверждено практикой финалистов предыдущих хакатонов.
2. **Wildberries API** открытый — начинайте с него. Первый рабочий парсер за 1 час даёт психологический импульс всей команде.
3. **Redis кэш** — если маркетплейс заблокирует, кэшированные результаты спасут демо.

### Питч-преимущества
4. **Говорите терминами 44-ФЗ** — НМЦК, обоснование цены, конкурентный способ закупки. Жюри будут люди из госзакупок.
5. **Живое демо с реальными товарами** — не на тестовых данных. Амир заранее готовит 5 запросов.
6. **Слайд "Следующий шаг"** — интеграция прямо в интерфейс zakupki.mos.ru как встроенный виджет. Покажите, что думаете о будущем продукта.

### Организационные преимущества
7. **Figma в первые 2 часа** — команды без макетов теряют день на "а как это должно выглядеть?". У нас источник правды с первого часа.
8. **Реальные тест-кейсы от Амира** — не придуманные, а взятые из реальных категорий портала поставщиков.
9. **Внутренний code review в День 2** — большинство команд идут на внешний review с "сырым" кодом. Мы приходим подготовленными.
